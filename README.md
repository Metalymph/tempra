# Fero

**Fero** is a fast, lightweight scripting language that compiles to native binaries.

> Write scripts. Ship binaries.

---

## Why Fero

Fero is built for a simple, direct workflow:

- **Write** a script.
- **Run** it instantly.
- **Compile** it into a native binary when needed.

No runtime bloat. No complex setup. Just a direct path from script to tool.

---

## Example

```fero
let files = fs.list_dir(".")?

for f in files {
    print(f)
}
```

```bash
# Run as a script
fero run script.fero

# Compile to a native binary
fero build script.fero
./script
```

---

## Core Design

Fero follows a simple, high-performance architecture:

- **Interpreter-first**: Fast startup, minimal overhead for scripting.
- **Native AOT (Cranelift)**: High-performance binaries for production.
- **Wasm Backend**: Portable output for web and sandboxed environments.
- **No JIT / Heavy VM**: Keeps the footprint small and predictable.

### Design Principles

- Minimal syntax with explicit semantics.
- No exceptions — explicit, typed error handling.
- Scripting-first ergonomics with a path to native output.

---

## Language Direction

Fero keeps the language small, consistent, and practical:

- **Versatile `for`**: Can be used as a statement or an expression.
- **Expressions Everywhere**: `if` and `match` are expressions.
- **Robust Types**: `struct` and `enum` as core data building blocks.
- **Structural Interfaces**: Static structural typing instead of a heavy trait system.
- **Flexible Entry**: Script mode (no `main`) or App mode (with entrypoint).

## Main Commands

```bash
fero run file.fero      # Execute script via interpreter
fero check file.fero    # Verify syntax and types
fero build file.fero    # Compile to binary/Wasm
fero install file.fero  # Install native binary to path
fero test               # Run package tests
fero fmt                # Format source code
fero repl               # Start interactive session
```

### Build Examples

```bash
# Optimized native build
fero build main.fero --target native --mode fast

# Small Wasm module
fero build app.fero --target wasm32-wasi --mode light
```

---

## Build Modes

- **`fast`**: Optimized for runtime performance. Enables aggressive optimizations like ARC elimination and inlining.
- **`light`**: Optimized for small binaries. Focuses on reduced code size and footprint.

---

## Compiler Pipeline

Fero IR is the central representation used by all execution paths:

`Source` → `Lexer` → `Parser` → `AST` → `HIR` → `Type Checking` → `MIR` → **`Fero IR`** → `Interpreter` \| `Wasm` \| `Native (Cranelift)`

---

## Wasm Strategy

Fero treats WebAssembly as a first-class target.

- **Wasm Output**: Generated by a dedicated backend, independent from Cranelift.
- **Wasm Hosting**: Handled separately (via Wasmtime) to allow secure execution of external modules.

---

## Native AOT Strategy

- **Powered by Cranelift**: Generates highly optimized machine code (x86_64, AArch64).
- **Native Only**: Cranelift is utilized strictly for native compilation, not for Wasm output.

### Status: Milestone 0.2
Fero is rapidly evolving. We currently have a functional core with:
- **Rich Syntax**: Arrays, Slices, Structs, Enums, Expressions-as-statements.
- **Strong Type System**: Static type validation for variables, functions, and standard methods.
- **Standard Library**: Core `os`, `fs`, `env`, and `builtins` (print, fmt, dbg, cmd).
- **Tooling**: A working CLI with `run` and `check` commands.

## Roadmap

### Current (Done)
- [x] Lexer, Parser, AST, HIR, Type Checker.
- [x] Fast, high-level Interpreter.
- [x] Initial Stdlib: `os`, `fs`, `env`.
- [x] Native Command Execution (`cmd`).
- [x] Array Slicing `xs[start..end]`.

### Next
- [ ] Productions-ready Cranelift AOT.
- [ ] Dedicated Wasm backend.
- [ ] LSP support (completion, go-to-definition).
- [ ] REPL enhancements.
- [ ] Shared backing storage for array slices.

### Long-term

- Advanced ARC optimization & elimination.
- Escape analysis for stack promotion.
- First-class SIMD support.
- Lightweight, scalable concurrency.
- Minimal effects system.
