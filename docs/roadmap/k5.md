# K5 — Phase Timings and Scripting Latency Baseline

K5 is **measurement**, not a formal proof milestone. K6 owns regression thresholds. Record reproducible artifacts and hardware **before** optimization or public comparisons. The default VM status must be measured rather than assumed.

## K5.1 — Measurement contract

Record the exact Git commit and dirty state, compiler build/profile, OS/architecture/CPU, installed binary version, tool versions, workload source and input hashes, working directory, warmups, sample count, stdout/stderr digests and process exit code. Distinguish installed binaries from `cargo run` (whose compilation overhead must not be silently included).

Report separately:

- **process-start-to-exit wall time**;
- compiler-stage timings (lexer, parser, HIR, typecheck, TIR, verifier, capability enforcement, bytecode, cache);
- VM compilation/cache miss and verified hit time;
- actual VM execution time;
- peak RSS and, where reproducible, CPU use;
- editing workflow latency (`check`, diagnostics, LSP).

OS filesystem-cache **cold** and **new-process cold start** are different conditions. Label them separately. Use raw measurements and declare each measurement boundary. Benchmarks must not be used as proof of language safety.

## K5.2–K5.5 — Delivery order

1. **K5.2:** structured per-stage compiler timings.
2. **K5.3:** release-installed process startup and memory baseline, with platform-specific RSS sampling and explicit runtime selection.
3. **K5.4:** representative scripts, modules, standard-library I/O, larger inputs and failure behavior.
4. **K5.5:** published raw data, methodology, baseline table and equivalent-workload validation. No comparative marketing claims before repeatability checks.

## Language comparison matrix

| Language | Execution mode | Build/transpile accounting |
| --- | --- | --- |
| **Tempra Script** | Verified stack VM, experimental until default promotion | CLI startup and compile/cache/runtime measured separately |
| Python | Pinned CPython | Interpreter startup included |
| JavaScript | Pinned Node.js | No TypeScript build cost |
| JavaScript | Pinned Bun | No TypeScript build cost |
| TypeScript | Bun TypeScript support | Document type-stripping/transpilation behavior |
| TypeScript | Node.js and pinned TS tooling | Report transpilation separately from execution |

Compare semantic equivalence, meaningful error behavior and real I/O, not a no-op against a workload with side effects. Source LOC/complexity and diagnostics are distinct qualitative dimensions, not substitutes for speed measurements.

The historical `scripts/k5_bench.py` reports **new-process wall time only** according to the inspected remote documentation; it is not evidence of peak RSS, complete compiler-phase timing or a physically cold OS filesystem cache. A harness self-test is not a benchmark result.
