# K5 — Phase timings and scripting latency baseline

Canonical K5 is **measurement**, not a formal proof milestone. K6 owns
regression thresholds. Record artifacts and hardware before optimizing.

## K5.1 Measurement contract (current)

Record exact git commit, dirty state, compiler version/build profile,
OS/arch/CPU, tool versions, workload input/data hash, working directory,
warmups, samples, stdout/stderr digests and exit code. Environment must
distinguish installed binaries from `cargo run` compilation overhead.

Metrics (separate): **process-start-to-exit wall time**, compiler phase
timings, VM warm/cold cache miss and hit, peak RSS, CPU, and for edit
workflow check/LSP responsiveness. OS filesystem-cache "cold" and
new-process "cold start" are not identical: label them separately.

## K5.2–K5.5 delivery sequence

- K5.2: structured per-stage timings (lexer, parser, HIR, typecheck,
  TIR, verifier, capability checks, bytecode and cache paths).
- K5.3: process startup and memory measurement with platform-specific
  RSS sampling and release-installed binary. Record runtime selection.
- K5.4: representative scripts, modules, stdlib I/O and larger inputs.
- K5.5: publish raw data, methodology and baseline table. No public
  comparative speed claims until equivalence is independently checked.

## Language comparison matrix

| Language | Execution mode | Build/transpile accounting |
| --- | --- | --- |
| Tempra | Ergal default VM | CLI startup and compilation/cache tracked |
| Python | CPython, version pinned | Interpreter startup included |
| JavaScript | Node.js | No TS build cost |
| JavaScript | Bun | No TS build cost |
| TypeScript | Bun TS support | Runtime/strip or transpilation behavior documented |
| TypeScript | Node.js + pinned TS toolchain | Report transpilation separately from execution |

Include source LOC/complexity, error-handling behavior and diagnostic
clarity as *separate*, qualitative/controlled comparisons. Run semantic
equivalence and output-hash tests first. For I/O, fix input data and
environmental effects; do not compare an optimized no-op with real work.

The initial `scripts/k5_bench.py` only measures **new process wall time**;
it does **not** measure peak RSS, compiler phases or physical cold cache.
Do not confuse the harness self-test with a Tempra benchmark.
