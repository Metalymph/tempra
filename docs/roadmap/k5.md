# K5 — Phase timings and scripting latency baseline

Canonical K5 is **measurement**, not a formal proof milestone. K6 owns
regression thresholds. Record artifacts and hardware before optimizing.

## K5.1 Measurement contract (current)

Record exact git commit, dirty state, compiler version/build profile,
OS/arch/CPU, tool versions, workload input/data hash, working directory,
warmups, samples, stdout/stderr digests and exit code. Environment must
distinguish installed binaries from `cargo run` compilation overhead.

Metrics (separate): **process-start-to-exit wall time**, compiler phase
timings, VM warm/cold cache miss and hit, peak RSS, CPU, and for edit
workflow check/LSP responsiveness. OS filesystem-cache "cold" and
new-process "cold start" are not identical: label them separately.

## K5.2–K5.5 delivery sequence

- K5.2: structured per-stage timings (lexer, parser, HIR, typecheck,
  TIR, verifier, capability checks, bytecode and cache paths).
- K5.3: process startup and memory measurement with platform-specific
  RSS sampling and release-installed binary. Record runtime selection.
- K5.4: representative scripts, modules, stdlib I/O and larger inputs.
- K5.5: publish raw data, methodology and baseline table. No public
  comparative speed claims until equivalence is independently checked.

## Language comparison matrix

| Language | Execution mode | Build/transpile accounting |
| --- | --- | --- |
| Tempra | Ergal default VM | CLI startup and compilation/cache tracked |
| Python | CPython, version pinned | Interpreter startup included |
| JavaScript | Node.js | No TS build cost |
| JavaScript | Bun | No TS build cost |
| TypeScript | Bun TS support | Runtime/strip or transpilation behavior documented |
| TypeScript | Node.js + pinned TS toolchain | Report transpilation separately from execution |

Include source LOC/complexity, error-handling behavior and diagnostic
clarity as *separate*, qualitative/controlled comparisons. Run semantic
equivalence and output-hash tests first. For I/O, fix input data and
environmental effects; do not compare an optimized no-op with real work.

The initial `scripts/k5_bench.py` only measures **new process wall time**;
it does **not** measure peak RSS, compiler phases or physical cold cache.
Do not confuse the harness self-test with a Tempra benchmark.

## 2026-11-10 identity and PRE-AOT use

K5.1 remains the benchmark **contract/harness**, while K5.2 remains **compiler
phase timings**. The Result implementation was tracked under canonical R.
K5/K6 measurements inform JIT removal, VM unification, REPL cold starts,
comptime staging, dependency reduction and eventual Ergal distribution, but
must not be conflated with a semantic soundness proof.

## K5.2a implementation slice — fresh single-source VM timings

A new **opt-in** `tempra timings [--json] file.tmpr` CLI command measures the
same fresh compilation path as `compile_to_bytecode_with_analysis`. No code
is executed. `--json` emits `schema_version: 1`, `mode`, `status`, `wall_ns`,
`phases[]` (`phase`, `elapsed_ns`, `success`) and nullable `error`. The report
on failure contains only the attempted phases, including the failing one.
The `wall_ns` measurement includes unclassified driver work; its value must
not be presented as the sum of phase measurements or process startup time.
The clock is monotonic but durations are naturally nondeterministic.

This first slice measures parse **including lexing**, HIR lowering, typecheck,
TIR lowering, TIR verification, capability/effects analysis, deny-enforcement,
bytecode lowering, bytecode verification and cache **write**. The profiled API
never reads cache artifacts. A cache write failure remains a warning and is
recorded as a failed phase rather than a failed compilation, matching the
existing compiler behavior.

**Not yet covered by K5.2a:** separate lexer timing; multi-module graph
loading/resolution/typechecking; the active default HIR run path; cache-hit
and invalidation timing; comptime's internal stage splits; process startup,
peak RSS and physical filesystem-cache coldness. Do not label K5.2 complete
until these supported paths are measured or their omission explicitly gated.

Validation: `just k5-phase-tests`, `cargo test --workspace`, then inspect
`tempra timings --json file.tmpr`. Record measured binary/profile, git commit,
input hash and environment in K5 baseline artifacts before quoting results.

## K5.2b implementation slice — module graphs and real cache reuse

`tempra timings --json file.tmpr` retains the K5.2a single-source **fresh**
behavior. Two opt-in modes are added, without executing user code:

- `tempra timings --json --cache file.tmpr` follows the actual single-source VM
  cache compatibility lookup. `cache_lookup` covers artifact read, decode and
  verification. `cache_hit: true` means that only the lookup was executed;
  `false` means a miss (including an incompatible or corrupt artifact) and the
  same fresh compilation path executes once. The cache write remains a warning
  on failure, consistent with normal execution. `cache_hit` is `null` for
  other modes; JSON schema v1 remains additive.
- `tempra timings --json --modules file.tmpr` measures fresh file/module-graph
  compilation. `module_graph` aggregates recursive filesystem I/O, lex/parse,
  HIR creation and import resolution; those subphases are **not separately
  measurable** in this slice. `module_typecheck` measures aggregate module
  checking, including compile-time evaluation internal to the typechecker;
  `tir_lower` includes generic specialization and module lowering. The normal
  verification, effects/enforcement and bytecode stages are then recorded.
  No module-graph bytecode cache is implied or created.

The measured APIs preserve the unprofiled driver code paths. The timing report
is observational; the phase list includes only stages reached. Durations vary
by run. `wall_ns` includes overhead outside reported phases and must not be
presented as process startup. Neither the nested costs of specialization and
comptime nor per-module timing detail is isolated yet. Those are explicit
follow-ups; K5.2 is **not** closed by K5.2b. Cache-hit profiles must not be
mixed with cache-miss profiles in benchmark aggregates.

Validation: `just k5-phase-tests`, workspace tests, CLI smoke for fresh,
`--cache` (twice) and `--modules`, plus bytecode reproducibility gates.
